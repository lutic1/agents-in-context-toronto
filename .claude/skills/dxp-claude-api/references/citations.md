# Citations, and the two FR-18 checks

Source: https://platform.claude.com/docs/en/build-with-claude/citations, checked 2026-11-12. The code reuses `client`, `EXTRACT_MODEL`, `TRIAGE_MODEL`, `system_blocks`, `checked` and `quote_in_source` from SKILL.md.

## What the citations feature gives

- Set `"citations": {"enabled": True}` on a `document` content block. No beta header. All current models.
- The reply is split into several `text` blocks. A block that makes a claim carries a `citations` list.
- For a plain text document each citation has `type == "char_location"`, `cited_text`, `document_index`, `document_title`, `start_char_index` and `end_char_index` (0-indexed, end exclusive).
- `cited_text` is extracted by the API from the document you sent. It is not generated by the model, so it is word for word by construction. The docs: citations are "guaranteed to contain valid pointers to the provided documents".
- Plain text is chunked into sentences. A citation is one sentence or several consecutive sentences, never part of a sentence.
- `cited_text` does not count toward output tokens.
- Works with prompt caching, token counting and the Message Batches API.

## What it does not give

- It cannot be combined with structured outputs. A document with citations enabled plus `output_config.format` returns a 400.
- The API does not guarantee that every field has a value or a citation. Check in code.
- A prompt that asks for JSON only succeeds but may return few or no citations.
- No confidence score. Add the support check below if the Record needs one from this path.
- Citations must be enabled on all documents in a request or on none.

## Which pattern to use

| | Structured outputs with a `quote` field (SKILL.md) | Citations |
| --- | --- | --- |
| Fixed JSON format | Guaranteed by the schema | Parsed from lines in your code |
| Quote is word for word | Model copies it; the exact check catches failures | By construction |
| Confidence per field | In the same call | Needs the support check |
| Character offsets for highlighting | Use `source.find(quote)` | Returned |

Start with structured outputs: one call, fixed format, confidence included, and the exact check fails closed. Measure the share of `quote_check == "fail"` on the gold set. Move the extraction pass to citations if that share is above about 5 percent.

## Citations pattern

The prompt wording is the one the documentation recommends for a citation per extracted value.

```python
FIELDS = ["diagnostic_name", "modality", "biomarker", "tumour_type", "stage_or_line", "sample_type",
          "clinical_use", "study_size", "key_result", "sponsor", "trial_id", "linked_drug", "regulatory_status"]

CITE_PROMPT = (
    f"Extract these fields from the document: {', '.join(FIELDS)}.\n"
    'Answer with one line per field in the form "field: value", and cite the document for each line. '
    "After the colon, write only the value, with no explanation or quotation. "
    "Leave out any field the document does not state."
)


def parse_cited_lines(content, allowed: set[str]) -> dict[str, list[dict]]:
    lines = [{"text": "", "cites": []}]
    for block in content:
        if block.type != "text":
            continue
        for i, part in enumerate(block.text.split("\n")):
            if i:
                lines.append({"text": "", "cites": []})
            lines[-1]["text"] += part
            if part.strip() and block.citations:
                lines[-1]["cites"].extend(block.citations)
    out: dict[str, list[dict]] = {}
    for line in lines:
        name, sep, value = line["text"].partition(":")
        name, value = name.strip(" *`-"), value.strip(" *`")
        if not sep or name not in allowed or not value or not line["cites"]:
            continue  # no colon, unknown field, empty value or no citation: drop it
        out.setdefault(name, []).append({
            "value": value,
            "quotes": [c.cited_text for c in line["cites"]],
            "spans": [(c.start_char_index, c.end_char_index)
                      for c in line["cites"] if c.type == "char_location"],
        })
    return out


async def extract_with_citations(item_text: str, title: str) -> dict[str, list[dict]]:
    resp = await client.messages.create(
        model=EXTRACT_MODEL,
        max_tokens=8000,
        output_config={"effort": "medium"},
        system=system_blocks(EXTRACT_PROMPT),
        messages=[{"role": "user", "content": [
            {"type": "document",
             "source": {"type": "text", "media_type": "text/plain", "data": item_text},
             "title": title,
             "citations": {"enabled": True}},
            {"type": "text", "text": CITE_PROMPT},
        ]}],
    )
    if resp.stop_reason != "end_turn":
        raise ItemFailed(f"stop_reason={resp.stop_reason}")
    found = parse_cited_lines(resp.content, set(FIELDS))
    for entries in found.values():
        for e in entries:  # still run the cheap check; it costs nothing
            e["quote_check"] = "pass" if all(quote_in_source(q, item_text) for q in e["quotes"]) else "fail"
    return found
```

Notes:

- `title` and `context` on the document are passed to the model but cannot be cited. Put metadata there, not in `data`.
- Send as `data` exactly the text you store as the Source item. The offsets and the exact check refer to that string.
- UNVERIFIED: the unit of `start_char_index` for text outside the Basic Multilingual Plane. Use the substring check as the test, and the offsets only for highlighting.
- Turning citations on or off between calls invalidates the cached system prompt. Keep one setting per pass.

## Exact-string check (FR-18, first half)

`quote_in_source()` in SKILL.md. It normalises Unicode form (NFKC) and runs of whitespace on both sides, then tests for a substring. Nothing else is tolerated: a changed digit, a dropped word, an ellipsis or two joined passages fail. A failed value is stored and not displayed.

## Support check (FR-18, second half)

"A field whose quote does not support its value also fails." A quote can be word for word and still not support the value. One cheap Haiku call per Record judges all fields at once.

```python
class SupportCheck(BaseModel):
    index: int
    supported: bool


class SupportReport(BaseModel):
    checks: list[SupportCheck]


JUDGE_PROMPT = (
    "For each numbered line decide whether the quote, read alone, states the value given for the field. "
    "Answer supported=false if the value needs information that is not in the quote."
)


async def judge_support(fields: list[dict]) -> list[bool]:
    listing = "\n".join(
        f'{i}. field={f["field"]} | value={f["value"]} | quote={f["quote"]}' for i, f in enumerate(fields))
    resp = await client.messages.parse(
        model=TRIAGE_MODEL,
        max_tokens=2000,
        output_config={"effort": "low"},
        system=JUDGE_PROMPT,
        messages=[{"role": "user", "content": listing}],
        output_format=SupportReport,
    )
    verdict = {c.index: c.supported for c in checked(resp).checks}
    return [verdict.get(i, False) for i in range(len(fields))]  # a missing verdict fails closed
```

Display a value only when both checks pass.
